3. Understanding the pipeline
The test job checks out the repository, installs Java 21, downloads Selenium and
JUnit, starts an HTTP server on port 5500, compiles the Java classes, and runs
JUnitCore. A failing test produces a nonzero exit status and fails the job.
The deploy job has needs: test, so failed tests block publication. It uploads
website/ and deploys it using the GitHub Pages actions. Only the default branch
is deployed. The previously published site remains after a failed test job.

Conclusion
CI can block regressions only when tests exercise the affected behavior and
assert its real outcome. Success messages alone do not prove persistence.
Negative input checks, rereading persisted data, and assertions after destructive
actions strengthen the tests. A passing suite is evidence of tested behavior,
not evidence that every possible defect is absent.
